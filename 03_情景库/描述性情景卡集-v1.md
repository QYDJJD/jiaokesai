# 虹桥描述性情景卡集 v1

版本日期：2026年10月10日。用途：突发事件下虹桥枢纽多方式协同疏运的案例归纳及方法讨论。已纳入铁路晚点、航空转场、台风运行调整及跨日过程；时段按实际服务条件记录，覆盖仍有缺口。用户确认描述性路线；范围修正及团队、导师确认状态见[决策记录](../项目管理/阶段收尾与决策记录-2026-10-10.md)。

来源编号、报道全文定位和统计口径以[案例与来源台账](../02_数据与案例/案例与来源台账-T-C4初稿.md)为准。卡片是报道复原；未取得运营原始日志。每张卡记录来源角色，已报道动作和研究建议分别列出。`NA`表示未知；不能以0或正常状态填补。主轴定义见[数据字典](../04_建模/数据字典与方法框架-v1.md)。

## 二 SC-E01：晚点旅客夜间多方式接续

**来源：** S01，上海市交通委[夜间保障记录](https://jtw.sh.gov.cn/xydt/20231226/6f4ed792491949fb871c7237e4d636ff.html)，页面署日期2023-12-19；事件2023-12-14至15日。URL日期不能代替事件日。

| 字段 | 内容与证据限制 |
|---|---|
| 边界及窗口 | 虹桥火车站晚点到达相关旅客；报道列车影响窗口23:00—次日05:00；并非完整需求观测窗口 |
| 已报道规模及时间 | 28班列车、10008名受影响旅客；21:28下达工作指令；次日05:10标记疏散完毕 |
| 已报道动作 | 轨交延时加开、夜宵公交加密、出租企业动员、ERC广播引导、现场监管 |
| 主轴 | P1、U、D、Q_aff均NA；R有部分运营动作线索，完整可用性/能力损失NA |
| 关键约束 | 旅客方向、常态剩余服务、道路场站、安全授权及各动作资源承诺未完整公开 |
| 结果字段 | 分方式部分实际运量可见台账；B_max、完整T_clear及方式分担率不可算 |

**可讨论的问题：** 晚点信息如何更新并支持各方式准备；何时确认服务方向、资源与实际生效。以上是研究问题，不能由保障记录断言原机制缺失。

**禁止转换：** 21:28不是已知首次可行动信息；23:00不是决策时点预知的目标到达时点，两者之差不赋值P1。六小时报道窗口不赋值D；10008人不直接赋值Q_aff；05:10不是有完整起点的T_clear；出租等待时间不赋值τ。不能以受影响总人数减去地铁公交运量推出租运量。

| 字段 | 内容与证据限制 |
|---|---|

| 时间和规模 | 报道02:18末班G161相关旅客完成疏运；7858为8月6日全天车辆服务量，不是旅客人数或事件新增车辆 |
| 主轴 | P1、U、D、Q_aff及完整R均NA；不能借用SC-E01的轨交、公交状态 |
| 未知约束与结果 | 全枢纽需求、其他企业/方式资源、方向、接令至生效链和最终完成范围均缺失；B_max、T_clear不可算 |

**可讨论的问题：** 把“请求、企业动员、驾驶员响应、到位和实际服务”分开记录；从企业报道不能推定平台或每位驾驶员受统一强制调度。

**比较边界：** E01与E02是不同独立事件，但公开人群和窗口不一致，只比较信息字段和动作过程，不比较疏运效率或大小等级。

| 字段 | 内容与证据限制 |
|---|---|

| 属性辨别 | 5月3日到达超32万人为报道实绩；5月4日38.6万、5日39.8万为文中预测，不因报道较晚而改作实绩 |

## 五 SC-E03：台风下方式限制、恢复与安全边界

**来源：** S03设施保障准备；AV02—AV06航空部署、调整、快照及恢复；OP05、OP06轨交调整及恢复。完整日期、转引层级和原文见两份补证表。同一台风不拆成多个独立事件。

| 字段 | 内容与证据限制 |
|---|---|
| 事件与群体 | 2024年9月15—16日贝碧嘉运行调整；未到场取消旅客、已到场需退改/离场旅客、实际到达待接续旅客分列 |
| 航空状态 | 取消快照、晚间取消通告和次日下午进出港恢复节点；不由架次换人数，不由恢复时点推清空 |
| 轨交状态 | 17号线全停、2及10号线部分区段限制；未证虹桥全部轨交不可用，不能推道路和其他方式同时停用 |
| 设施与安置 | 已报道检查、加固、休息保障及场所准备；启用、入住、容量与持续时长未知 |
| 主轴 | P1、U、D、Q_aff为NA；R可记录已核线路/区段/时段限制，完整损失与剩余能力NA；D不以停运时长替代 |
| 约束与结果 | 安全通行、场所承载、授权、实际人群与时间链缺失；B_max、T_clear不可算 |

**研究问题：** 如何分方式、时段更新可行服务，避免航空恢复后自动认定陆侧接续完成；如何给不同旅客状态分别设置入口和目标。

**候选分支：** 核运输安全和可用路径，必要时衔接留候、安置或专业处置。此为研究接口，不是正式指令；未知安全不推定正常或实际禁用。安置不计为继续疏运完成。

## 七 SC-E04：大雾下航空备降与跨机场转场

**来源：** AV01，上海机场集团[2014年运营纪实](https://www.shairport.com/xwg/info_itemid_19250.html)，2014-02-08发布；事件为1月30日凌晨至31日清晨。

| 字段 | 内容与证据限制 |
|---|---|
| 边界与对象 | 虹桥承接备降或转场出港旅客；浦东地面转运还含宾馆、附近居所，不合计为虹桥现场人群 |
| 已报道动作 | 巴士协调、现场警务上客与转场组织、机场航司信息互核及滚动发布 |
| 地点与目标 | 原计划机场、实际到达机场、后续登机或城市目的地分列；转场不等同于城市离站 |
| 主轴与约束 | P1、U、D、Q_aff及完整R为NA；道路、上客、接收服务和授权缺日志；不用低能见度运行时长作D |
| 网络版本 | 2014历史配置，不能借用2024年底开通的机场联络线或2026车辆安排 |
| 结果 | 航班、车辆、车次与人次口径分开，局部值守时长不作τ或全事件T_clear |

**研究问题：** 跨机场需求怎样确认实际地点和后续目标，避免将所有备降旅客视为陆侧疏运人群。详细统计只在补证表保存，不重复拼接全枢纽总量。

## 十 维护规则

新增事实先回补来源台账，再更新卡片及[覆盖表](情景覆盖矩阵-v1.md)。缺失字段按[字典](../04_建模/数据字典与方法框架-v1.md)保留缺失原因；重复报道归同事件。假设扩展另用SC-H编号，记录父事件、改变字段、取值依据及筛查结果，不能混入真实案例计数。

本次完成助手技术整理；成员人工复核、实际日志核对及正式预案授权核查待完成。
