# 虹桥描述性情景卡集 v1

版本日期：2026年10月10日。用途：主研究夜间晚点旅客继续疏运的案例归纳及方法讨论。路线与写作范围由用户确认，团队及导师确认状态见[决策记录](../项目管理/阶段收尾与决策记录-2026-10-10.md)。

来源编号、报道全文定位和统计口径以[案例与来源台账](../02_数据与案例/案例与来源台账-T-C4初稿.md)为准。卡片是报道复原；未取得运营原始日志。每张卡记录来源角色，已报道动作和研究建议分别列出。`NA`表示未知；不能以0或正常状态填补。主轴定义见[数据字典](../04_建模/数据字典与方法框架-v1.md)。

## 二 SC-E01：晚点旅客夜间多方式接续

**来源：** S01，上海市交通委[夜间保障记录](https://jtw.sh.gov.cn/xydt/20231226/6f4ed792491949fb871c7237e4d636ff.html)，页面署日期2023-12-19；事件2023-12-14至15日。URL日期不能代替事件日。

| 字段 | 内容与证据限制 |
|---|---|
| 边界及窗口 | 虹桥火车站晚点到达相关旅客；报道列车影响窗口23:00—次日05:00；并非完整需求观测窗口 |
| 已报道规模及时间 | 28班列车、10008名受影响旅客；21:28下达工作指令；次日05:10标记疏散完毕 |
| 已报道动作 | 轨交延时加开、夜宵公交加密、出租企业动员、ERC广播引导、现场监管 |
| 主轴 | P1、U、D、Q_aff均NA；R有部分运营动作线索，完整可用性/能力损失NA |
| 关键约束 | 旅客方向、常态剩余服务、道路场站、安全授权及各动作资源承诺未完整公开 |
| 结果字段 | 分方式部分实际运量可见台账；B_max、完整T_clear及方式分担率不可算 |

**可讨论的问题：** 晚点信息如何更新并支持各方式准备；何时确认服务方向、资源与实际生效。以上是研究问题，不能由保障记录断言原机制缺失。

**禁止转换：** 21:28不是已知首次可行动信息；23:00不是决策时点预知的目标到达时点，两者之差不赋值P1。六小时报道窗口不赋值D；10008人不直接赋值Q_aff；05:10不是有完整起点的T_clear；出租等待时间不赋值τ。不能以受影响总人数减去地铁公交运量推出租运量。

## 三 SC-E02：出租企业多渠道动员

**来源：** S02，文汇网[强生出租保障报道](https://www.whb.cn/zhuzhan/cs/20230807/533824.html)，2023-08-07；事件涉及8月6日至7日。

| 字段 | 内容与证据限制 |
|---|---|
| 扰动及对象 | 山东地震影响列车抵沪；强生企业在虹桥的动员与疏运记录 |
| 已报道动作 | 车载信息、群消息和电话动员，现场调度与驾驶员引导 |
| 时间和规模 | 报道02:18末班G161相关旅客完成疏运；7858为8月6日全天车辆服务量，不是旅客人数或事件新增车辆 |
| 主轴 | P1、U、D、Q_aff及完整R均NA；不能借用SC-E01的轨交、公交状态 |
| 未知约束与结果 | 全枢纽需求、其他企业/方式资源、方向、接令至生效链和最终完成范围均缺失；B_max、T_clear不可算 |

**可讨论的问题：** 把“请求、企业动员、驾驶员响应、到位和实际服务”分开记录；从企业报道不能推定平台或每位驾驶员受统一强制调度。

**比较边界：** E01与E02是不同独立事件，但公开人群和窗口不一致，只比较信息字段和动作过程，不比较疏运效率或大小等级。

## 四 SC-G01：常态返程高峰对照

**来源：** S04，[市公安局返程保障记录](https://www.shanghai.gov.cn/nw31406/20260508/c349732ae3044a149ce33b51331d96f9.html)；S05，[五一地铁安排](https://www.shanghai.gov.cn/nw17239/20260430/95e18d877dd6423cbba1f42d25c692ca.html)。

| 字段 | 内容与证据限制 |
|---|---|
| 对照范围 | 2026年5月3—5日返程高峰；日到达报道，不直接等于夜间待疏运需求 |
| 属性辨别 | 5月3日到达超32万人为报道实绩；5月4日38.6万、5日39.8万为文中预测，不因报道较晚而改作实绩 |
| 实际空间动作 | 到达出口分流及P10 B1临时上客组织；30个临时上客泊位是设施数量，不是每小时运输能力 |
| 事前运营安排 | 相关轨交定点加开计划及换乘限制；计划执行、实运量和效果待核 |
| 主轴与结果 | P1、U、D、Q_aff及完整R均NA；部分方向与空间线索可描述；不算B_max、T_clear |

**可讨论的问题：** 有准备的常态高峰与突发晚点的信息、方向和空间组织有哪些差异。不能由高峰日人多便认定启动某行政应急等级，也不跨年份借设施配置填E01能力。

## 五 SC-E03：继续疏运与安全安置边界

**来源：** S03，上海市国资委[台风保障材料](https://www.gzw.sh.gov.cn/shgzw_zxzx_gqdt/20240918/87a233dab9064ff684b354195059008d.html)，2024-09-18发布，上海地产集团段。

| 字段 | 内容与证据限制 |
|---|---|
| 已报道准备 | 停车库和蓄车场设施检查加固、休息区保障、滞留点准备 |
| 卡片作用 | 提醒运输可用性与旅客安全优先核查；若运输不安全，应转入适用安置/救援流程 |
| 未证事实 | 滞留点实际启用、入住人数、各方式停运范围及时间均NA |
| 主轴与约束 | P1、U、D、Q_aff及完整R均NA；安全、场所容量、启用授权和特殊人群保障待核 |
| 完成定义 | 安全安置与完成继续出行分别记录；不能把临时安置自动计作疏运完成 |

**可讨论的问题：** 怎样在动作接口保留“运输安全未确认，先核查或转介”的分支。该分支为拟研究规则，不是已确认现行指令；未知安全状态也不等同于实际禁运。
