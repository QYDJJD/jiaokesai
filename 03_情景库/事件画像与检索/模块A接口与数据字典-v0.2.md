# 模块A接口与数据字典 v0.2

整理日期：2026年10月28日。研究原型；与[画像检索](README.md)及[网络模型](../../04_建模/多方式网络优化/README.md)并行，不替换现有数据。团队尚未确认正式接口。

## 一 基本流程

当前画像 → 生成检索词 → 本地案例检索 → 按需调用外部搜索适配器 → 网页或模拟文档提取候选 → 与固定指标比较 → 多来源去重 → 展示证据及调查建议 → 人工检查并填写当前值 → 形成带来源的画像版本。现有`research_workflow.py`实现检索词、**模拟提供器**、规则候选、片段位置、去重和内存中的确认动作；没有实现在线搜索、网页下载、真实性校验、持久化入库或自动画像更新。

提供器接口为`kind`（mock或online）和`search(terms)`。接入真实提供器时必须实际检索和提取、标识搜索及抓取时间、对来源与正文进行核查，不允许用模拟文本冒充联网结果。提供器当前不支持服务器读取任意URL；后续网络实现需域名与重定向限制、超时、内容大小及编码限制，防止访问本机和内部地址。

## 二 数据结构与证据

| 实体 | 核心字段 | 数据属性 |
|---|---|---|
| 当前画像 | PORTRAIT-01事件ID、事件族、字段值、状态、来源、as_of | observed、forecast、assumption、unknown；unknown必须为空 |
| 历史案例 | 独立事件族、类型、时空、人群、来源、历史事实 | 当前catalog是示例格式；不把计划或演练当成实际事件 |
| 查询 | 当前已知事件类型、诱因、地点、时段 | 原型仅形成词组，不上网或发送数据 |
| 文档 | 标题、URL、发布方、发布日期、采集时间、提取文本 | MockProvider由调用者提供演示文本；online尚无实现 |
| 候选指标 | 固定indicator_id、名称、推荐理由、多个证据、确认状态 | 值默认null；同一指标可聚合多来源，不迁移历史数值 |
| 证据 | URL、标题、发布方、发布日期、采集时间、原文短片段、字符起止、文本SHA-256、提供器类别、来源状态、可信度说明 | 字符位置是提取文本中的Python字符偏移；原文复核与可信度均待人工 |
| 人工确认 | 当前事件值、确认人、时间 | 内存函数仅返回新对象，尚无表单或持久化；不代签团队成员 |

确定来源可靠性应分别核发布主体、原始/转述、日期、事件与统计范围、证据是否支持结论。自动系统可以展示来源属性，不应将政府域名自动变成“已验证”。文档原始快照、正文和证据保护需后续设计。

## 三 检索、抽取、去重与排序

本地案例采用现有加权字段匹配；在线搜索适配器预留查询词，尚未实现。指标抽取当前仅对小型预置术语表进行字面命中，证据片段为命中词，属于演示线索而非完整上下文证明。用稳定指标ID合并多来源，同一URL和片段去重；明确列入固定清单的同一指标ID不重复推荐。

固定字段范围可能比推荐指标更粗，例如已有资源概述并不代表已知出租到达率。2026年11月19日更新后，这类候选仍保留，并标记已有相关字段、需核实细节；后续仍需领域字段字典、别名和层级对应。当前输出按预设规则顺序，**没有根据权威性、相关性和时效性实现可信排序**；不能宣称已验证的指标生成。

## 四 与MILP的输入与缺口

| 需求 | NETWORK-CARD-02现状 | 下一步 |
|---|---|---|
| 分时需求、初始候客、方向 | groups、profiles支持分群体和多过程 | 补画像到群体/数组的逐项转换；当前桥接限单合成过程 |
| 交通资源及场站 | nodes、modes、links、pools、facilities | 制定分时能力及权限证据来源，补司机上岗与特殊人群需求 |
| 安全容量 | 节点/全局容量为硬约束 | 未获安全条件时停止生成实际建议，无法通过牺牲安全换取低成本 |
| 不确定性 | 多输入过程共用预约和历史一致约束 | 资源到位延迟、道路变化等需显式情景，不推断为所有情况有保障 |
| 未疏运和缺口 | 最终必须完成；资源不足时可能返回不可行 | 扩展终点剩余变量、分层目标及独立核算；未实现前不报告最小缺口 |
| 公平与重点群体 | 支持群体区分，不自动给公平目标或无障碍服务 | 与团队约定指标及能力要求后再设计 |
| 权限与备用 | 人工配置可协调方式和服务日历 | 未获批资源不得作为现实可执行方案；为不同约束分别建卡、求解并核对 |

## 五 入库闭环与验收

候选仅能由人员复核原始来源、时间、对象、片段后决定接受或拒绝；需要时填入当前值、来源和确认时间。历史材料入库需独立事件去重、字段清理、版本及修改人记录；未经确认保留候选，不改已发布的种子库。接口与数据治理的这些持久化操作尚待实现。

可执行检查见`test_research_workflow.py`：验证证据片段位置、模拟属性、去重、具体固定指标排除、宽泛字段保留细项、显式确认和元数据缺失拦截。测试结果只说明程序行为，不证明线上检索质量或指标实际适用性。
