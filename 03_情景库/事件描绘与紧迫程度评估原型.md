# 事件描绘与紧迫程度评估原型

版本：事件评定原型-01。日期：2026年10月23日。

## 1 研究目标

以五维及必要补充字段描绘事件，输出处置紧迫程度、任务规模、客流压力、信息状态和提示原因，再进入后续交通处理。主等级回答“必须多快行动”，不回答“必须派多少辆车”。原“最低资源保障层次”属于不同问题，保留为历史试验。

200人的异常可能只剩5分钟准备，因此紧迫；1200人的异常若提前120分钟获知，任务更大，但具有准备窗口。二者不应被压成“人越多越紧急”的一条序列。

上述例证及页面中的直接危险用例仅为讲解模型所选的参数组合，不构成三种事件类型。实际输入先逐维记录条件，同一事件可同时出现时间紧、规模大、服务受限及信息不确定等特征；等级是计算输出，不要求预先选择。页面默认直接录入参数，可选示例折叠保留。已核实异常与直接危险字段登记处置前提和优先规则，不代替完整事件画像。

本课题提出“准备时间比较＋客流目标检查＋危险优先”的研究原型。外部资料支持分项组织和时间过程意识，不替本课题证明四档组合规则、参数标定或预测准确率。

## 3 输入怎样组织

| 层次 | 字段 | 含义与口径 |
|---|---|---|
| 事件基本事实 | 已确认异常、常态变化、直接安全危险或尚未核实 | 先核事件信息，不能只凭提前量认定为法定突发事件 |
| 五维之一 | 距冲击开始的剩余时间 | 从当前时点到预计运行冲击开始，区别于“消息收到后已经过去多久”；0表示冲击已开始，不重建此前过程 |
| 五维之二 | 到达过程不确定性 | 单一进入曲线，或平稳、80%在前1/3、80%在后1/3三种假设分别计算；不赋发生概率，不声称覆盖全部可能过程 |
| 五维之三 | 新增旅客进入持续时间 | 进入开始到最后一批进入的持续时间，不用天气或停运时长替代 |
| 五维之四 | 新增待接续人数 | 本次新增，当前已候客另列，不重复计数 |
| 五维之五 | 方式与空间服务状态 | 当前演示以每小时兼容有效能力及候客控制上限表达；线路、方向和共享空间尚未逐项展开 |
| 评估补充 | 准备所需时间 | 信息核实、人员到岗、引导等先期准备时间，与车辆需求及清空时间分开 |
| 评估补充 | 当前候客、候客上限、末批进入后的完成余量 | 用于计算积压与目标缺口。安全标准和研究目标应分别记录来源 |

固定底板继续保存相对稳定条件，时段模板保存常态供给与需求规律，事件层保存当次扰动。五维为主要组织字段，不要求所有判级信息都挤入五个数值。

## 4 怎样计算和确定研究提示等级

### 4.1 分项计算

准备时间余量＝距冲击开始的剩余时间－所需准备时间。小于0表示无法按所填时长在冲击前完成准备；等于0表示刚好可行，不意味着存在额外缓冲。这个边界来自时间可行性。所需准备时间应来自过程分解、适用要求或声明的研究假设，不设未经证明的统一“少于某分钟就是应急”阈值。

客流使用分段连续队列。有效服务按同一群体、同一时间单位计算：冲击前先消化当前候客，冲击后逐段比较进入和服务，队列不得为负。分别报告候客峰值、控制上限占比、全部接续时间及截止剩余；没有可用服务且任务非零时标为当前条件下不能全部完成，不捏造有限清空时间。

不确定过程逐一计算，保留结果范围与目标缺口。未知能力不填0，未核实的事件性质不自动判为安全。已确认直接危险不等待其他数值补齐，也不会由人数小而降级。

### 4.2 四档研究提示

按以下优先顺序执行，不作加权平均：

1. **一级·立即核验处置：**直接安全危险已确认，或当前候客超过所设上限，或需要准备的异常／目标缺口在冲击已开始时仍存在。
2. **待核实：**事件性质未知；或能力未知且无法判断是否有客流目标缺口。保留已知危险提示及可计算部分；已知异常的时间紧迫提示可暂定，必须标注能力未核实。
3. **二级·紧急准备：**有已确认异常或所检查过程有目标缺口，冲击尚未开始，但准备时间余量小于0。
4. **三级·提前准备：**有已确认异常或预测目标缺口，准备时间余量不少于0。
5. **四级·常态关注：**没有已知异常、直接危险或所检查过程的目标缺口。短提前量本身不单独触发应急认定。

一级至四级为本课题当前原型的界面名称，不等同于四级官方预警或响应。提示内容限于核验、报告、准备、监测及按适用预案保护人员，不自动发布警报、不配置车辆。

### 4.3 当前为何不先加权

人数、持续时间和服务能力已经共同进入客流计算，若再对它们与积压分别加权，容易重复计入同一影响。普通加权平均还可能使“人数少”抵消“危险迫近”。本原型先让明确危险和准备不可行条件优先，其余画像并列展示。将来如引入综合分数，应明确其用途、权重依据、重复计量处理及敏感性，并与当前规则比较；复杂运算不是有效性的替代证明。

## 5 可复现例证与验证

演示统一假设：准备20分钟、进入30分钟、有效服务300人/小时、当前候客0、候客上限500人、末批进入后60分钟完成。

| 情景 | 结果 | 说明 |
|---|---|---|
| 已确认异常；200人，剩5分钟 | 二级·紧急准备；准备缺15分钟；三过程峰值50—110人，均满足客流目标 | 时间紧迫可以与较小任务规模同时存在 |
| 已确认异常；1200人，剩120分钟 | 三级·提前准备；准备余100分钟；三过程均有客流目标缺口 | 任务较大需要后续细化，不直接等同于最紧迫 |
| 已确认直接人身危险 | 一级·立即核验处置 | 危险规则优先，人数少或参数缺失不抵消 |
| 无异常；200人、常态示例能力、剩1分钟 | 四级·常态关注 | 短提前量不能独自定义应急 |

15项规则检查覆盖准备时间恰好相等、冲击已开始、直接危险、当前超限、未知能力、未知性质、0需求和无服务、缺参等边界；648组与独立累计需求减服务及反射队列计算一致。它们验证代码机制，不证明实际阈值已校准，也不表示真实分类准确率。

## 6 下一阶段的验证重点

以既有五维区分作用材料为基础，检查主等级随可用时间减少、所需准备增加是否符合预期；固定人数改变节奏和能力，核客流画像是否改变；核未知信息、接近边界与高危险条件不被错误平均。比较不同准备假设和控制目标时，分别报告哪些等级稳定、哪些敏感。公开资料用于核事件事实和时序，无法识别的参数以范围假设进行实验。

主等级目前主要反映准备窗口；发展速度、受影响区域、弱势群体与信息更新可靠性等还未形成经过核验的严重性模型。五维或扩展字段的选择，应以能否改变事件判断为依据，不因增加维数而宣称更准确。真实准确率及官方阈值映射不在当前已完成范围。后续交通优化作为下一层应用，不再承担证明本次紧迫分级的主体任务。
