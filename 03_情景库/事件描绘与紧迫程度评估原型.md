# 事件描绘与紧迫程度评估原型

版本：事件评定原型-02。日期：2026年10月25日。

## 1 本版完成什么

主线是“组织情景参数 → 分项计算 → 判断处置紧迫程度 → 保存证据与版本 → 为后续处理提供输入”。主等级回答需要多快核验和准备；人数、候客压力与完成目标另列，不按等级推算车辆数。

[单文件演示](../07_成果输出/情景库思路演示.html)现可新建、载入、复制情景，引用底板和时段模板，填写参数与逐项证据，计算、保存新版本、导入导出及比较。六组成对检查用于说明参数的作用。首页不强制选择事件类型，初始不自动生成等级；修改输入或来源后隐藏旧结果，须重新计算。

后续运输动画仍是独立示意；[组员的同资源时序优化](../07_成果输出/演示版本/2026-10-25-同资源时序优化/README.md)保留，尚未与当前情景卡自动联动。

## 3 分层复用：不为每次事件重建全部条件

| 层次 | 保存内容 | 当前实现 |
|---|---|---|
| 共用底板 | 相对稳定的对象和空间边界 | 演示接续区、虹桥历史事件描述性底板；有标识、版本和边界，未虚构实际设施容量 |
| 常态时段模板 | 日夜规律等基准条件 | 日间1200、夜间300人/小时为合成参照；历史夜间能力未知 |
| 当次扰动 | 本次预测、人数、进入期、服务变化和初始状态 | 选时段提供初值，实际有效能力可覆盖并记录证据 |
| 版本 | 同一情景的信息更新 | 保存增加版本、保留原版；复制产生新标识并引用父卡，记录参数改动 |

两个底板、四个时段选项是演示注册表，尚无任意新增底板的编辑器。模板证明的是复用结构，未形成真实标定库。完整网络工作台仍保存自身完整输入，尚未迁移为这一注册表。

## 4 五维与补充字段

| 主维度 | 录入和口径 | 计算作用 |
|---|---|---|
| 信息时间 | 首次可行动信息时点、当时预计冲击开始时点；当前评估时点 | 前两个时点之差是首次信息提前量，供追溯，不能与当前剩余时间混用 |
| 预测不确定性 | 当前预计最早、最晚多久开始冲击；预测更新时间、证据属性 | 检查开始窗口，保留可能等级；人数、能力等仍为单值，对它们可另存范围假设版本，未自动传播全部不确定性 |
| 新增旅客进入持续时间 | 第一批至最后一批进入候客边界的分钟数 | 与人数和节奏形成进入速率，不用天气时长或铁路影响窗口直接替代 |
| 新增待接续人数 | 本次新增，不含当前已候客 | 确定任务规模，参与队列计算；不直接等于报道全部受影响人数 |
| 方式与空间服务状态 | 本批人群兼容的有效能力；初始候客和控制上限 | 与需求共同形成队列；聚合能力须已处理去向不兼容及共用限制，未展开线路瓶颈 |

**进入节奏与预测不确定性分开。** 均匀、前1/3进入80%、后1/3进入80%是三种形状假设，可单选或分别检查。它们不具有默认概率，也不是全部不确定过程的分类。

**准备所需时间**包括信息核实、人员到岗和引导准备，不等于运输清空时间。**末批进入后完成余量**是最后一批进入以后，允许继续接续的时长。候客不超上限、规定时间内完成是两个主目标，个人最长等待未加入新门槛。

异常与直接危险分别核实，均允许未知；这两个状态不是互斥事件类型。空白数值为未知，0表示明确输入的零。默认20分钟准备、500人控制上限、60分钟完成余量均为研究假设。

### 4.1 逐项证据与真实材料

每个参数保存“事实、预测、研究假设、未知”属性、来源和说明。修改数值自动改为“研究假设，尚未核验”，有依据后可重新确认。填写来源不等于已自动核实真实性；背景事实不能随数值修改变成当时预测。

内置2023年12月14—15日虹桥降雪晚点原型来自[仓库已核的交通委报道](https://jtw.sh.gov.cn/xydt/20231226/6f4ed792491949fb871c7237e4d636ff.html)。28班列车、10008名受影响旅客、21:28工作指令和夜间影响窗口支持背景描述，不能分别直接赋值为新增待接续人数、首次获知时间和人群进入期。有效能力、初始候客、当前预测区间保持未知，因此不输出确定主等级。复制并添加假设可以做条件实验，不增加已验证真实事件数量。

## 5 计算与判级

### 5.1 分项计算和缺参处理

准备余量＝当前预测剩余时间－准备所需时间。小于0表示按所填过程无法在冲击前完成准备，等于0表示恰好可行。0边界来自时间可行性，不是未经证明的统一“少于若干分钟即应急”标准。

客流为连续分段队列，采用恒定有效服务率。预计进入前先消化当前候客，进入后逐段累加需求与服务差额，队列不为负；报告峰值、截止剩余和全部完成时刻，时间均从当前评估起算。非零任务且无服务时，不产生有限完成时间；无人且无新增任务可以为0。

缺准备时间时可保留队列、暂缓时间判级；缺上限或完成余量时可保留峰值、暂缓相应目标检查。已知直接危险、已知当前超限不等待其他参数补齐。

### 5.2 四档研究提示的优先规则

| 条件 | 输出 |
|---|---|
| 已确认直接安全危险，或当前已候客超过所填上限 | 一级·立即核验处置，其他缺参单列 |
| 有已核异常或所检查过程的目标缺口，且预测冲击已开始 | 一级·立即核验处置 |
| 同上，冲击尚未开始，剩余时间小于准备时间 | 二级·紧急准备 |
| 同上，剩余时间不少于准备时间 | 三级·提前准备 |
| 已核只有常态变化、未发现直接危险，所检查客流目标全部满足 | 四级·常态关注 |
| 不能建立上述条件 | 暂不能确定，保留已知分项与信息缺口 |

异常已确认但能力未知时，可给时间紧迫的条件性提示，不能声称客流目标已满足。直接危险未知时，不输出“已确认安全”。三级表示存在准备窗口，不表示影响小。

**用户已选择的区间规则：**预计5—30分钟后开始、准备需20分钟，主提示按最早5分钟给二级，同时保留二、三级，准备余量−15至10分钟。页面列实际得到的等级，不强行补成连续等级，不赋概率。

客流范围由端点计算，可能等级同时检查窗口内“已开始”和“恰好能准备”的边界，避免0—30分钟窗口遗漏中间的二级。该处理只适用于当前恒定服务、固定任务群体和声明曲线。增加开闭站日历、跨方式选择或共享资源后，中间时点可能更差，不能未经证明继续沿用端点与当前边界规则。

### 5.3 目前为何不用综合权重

人数、持续时间和能力已共同进入队列，再将它们与积压分别加权容易重复计量。普通平均也可能让“人数少”抵消“直接危险”。本版先用优先规则，其余画像并列。如果以后设置综合评分，需要另论用途、权重依据、重复计量和敏感性；复杂运算本身不证明方法可靠。

## 6 成对检查与验证

除特别说明外，合成实验使用准备20分钟、进入30分钟、初始候客0、上限500人、完成余量60分钟；能力均为研究假设。

| 只改变什么 | 条件甲 → 条件乙 | 结果及解释 |
|---|---|---|
| 当前剩余时间 | 200人、能力300人/小时，5 → 30分钟 | 二级 → 三级；峰值同为50—110人，紧迫与规模可分开 |
| 进入节奏 | 200人、剩30分钟，均匀 → 前段集中 | 同为三级，峰值50 → 110人；同级仍需细化 |
| 有效能力 | 800人、剩30分钟、已核仅常态变化，300 → 1200人/小时 | 三级 → 四级，峰值650 → 200人；不是仅看人数 |
| 进入持续时间 | 800人、能力600、上限400、已核仅常态变化，30 → 120分钟 | 三级 → 四级，峰值500 → 0人；同规模不等于同强度 |
| 预测开始窗口 | 200人，30—30 → 5—30分钟 | 三级 → 二级主提示，并保留二、三级；不按平均预测掩盖早冲击 |
| 当前候客 | 持续时间缺失，600 → 400人 | 一级 → 二级时间提示，客流过程均暂缓；缺参不隐藏已知超限 |

这些检查验证当前规则响应，不是五维独立充分、真实分类准确率或实际处置改善。真实原型用于核证据能否支持赋值，不伪造完整事件回放。

可复现脚本：[验证事件评定](../06_实验验证/事件评定验证/验证事件评定.cjs)。仓库根目录运行 `node 06_实验验证/事件评定验证/验证事件评定.cjs`。

24项检查通过，其中648组队列与独立累计流量反射计算一致；另核区间中间时点被端点客流范围包含及跨边界时可能等级不遗漏。检查覆盖危险/超限缺参优先、准备边界、未知与0、无服务、部分可算、首次时间独立、版本不覆盖、复制证据、包往返、旧等级忽略及冲突拒绝。浏览器另核旧结果隐藏、本地版本刷新保留、区间提示及比较。

## 7 保存复用与展示

卡片保存标识、版本、父卡、底板/时段引用、元数据、参数、逐项证据、公开事实和参数改动。导出包含注册表版本及按当前规则复算的结果；导入检查格式、范围、模板定义和同标识同版本冲突，不信任外带旧等级。

库在当前浏览器本地存储。离线文件与本机网址可能有不同存储空间，跨设备或浏览器需导出、导入。最多100个版本、导入不超过1.5MB，数字输入范围是当前演示的程序限制，不是运营标准。这不是多人数据库、GitHub自动同步或实时接入；单卡导出可以是版本0草稿，整库导出不含未保存修改。本页不自动倒计时，信息更新后须人工更新剩余分钟再评估。

建议向老师展示三步：

1. 载入“预测开始窗口5—30分钟”并计算：200人不多，但20分钟准备可能来不及；看主提示、可能等级及峰值。
2. 修改一个参数再计算，或展示六组成对检查：说明每个维度改变什么、同等级为何仍需保留细节。
3. 载入虹桥材料原型：说明事实支持什么、哪些未知；复制后做假设实验，区分公开事实与合成计算。

## 8 结论与边界

已走通参数录入、条件计算、解释判级、证据记录、版本复用及比较的演示链，可以检验机制并支持导师讨论字段和规则。

尚未建立经验证的影响严重性模型、预测概率模型、实际阈值映射或带服务日历的网络不确定性传播；尚未自动转换为后续排班输入。学生阶段可继续公开证据下的范围实验与规则对照；运营后台接入、现场核定和正式发布权限是实际应用条件，不作为必须完成的研究验收项。
