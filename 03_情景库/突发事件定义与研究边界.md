# 突发事件定义与研究边界

梅玉坤负责部分：T-B1 突发事件定义。修订日期：2026年10月8日。用途：为情景库确定事件输入口径，说明本课题如何把事件原因转译为可用于协同调度分析的运营状态。

本文件只界定研究对象，不替代现行应急预案的事件定级、组织响应或现场处置规则。正式响应级别、处置权限和安全措施仍以适用法律、预案及运营单位规定为准。本课题讨论的是安全条件允许继续疏运时，突发事件造成的客流、能力、时间和信息条件变化如何进入情景库。

## 一 权威定义与研究收窄

《中华人民共和国突发事件应对法》将突发事件界定为突然发生，造成或者可能造成严重社会危害，需要采取应急处置措施予以应对的自然灾害、事故灾难、公共卫生事件和社会安全事件。该定义解决的是应急管理总体对象，覆盖范围很广，包含生命救援、公共安全、医疗救治、社会稳定和恢复重建等任务。

本课题不研究所有突发事件，而研究其中会显著扰动综合交通枢纽运行、引发多方式协同疏运需求的事件后果。可采用如下工作定义：

> 本课题所称突发事件，是指自然灾害、事故灾难、运营异常、公共安全事件或外部交通扰动等因素，导致超大规模综合交通枢纽在特定时间和空间范围内出现客流到达异常、服务能力下降、换乘链受阻或运力供需失衡，并需要启动跨主体交通组织和多方式协同疏运措施的运营冲击。

这一定义的重点不是灾害名称，而是事件对枢纽运行状态的影响。火灾、暴雨、设备故障、列车晚点和道路管制都可以进入研究，但进入情景库的依据不是它们属于哪一类事件，而是它们造成了什么可观测的疏运压力和能力约束。

## 二 纳入与排除边界

| 对象 | 是否纳入 | 处理方式 |
|---|---|---|
| 暴雨、台风、暴雪等天气导致的高铁或航班延误 | 纳入 | 记录预警提前量、到达不确定性、夜间集中到达和地面交通能力变化 |
| 铁路、航空、轨道或场站设备故障造成的晚点、中断或换乘受阻 | 纳入 | 记录受影响人群、受影响方式、空间范围、能力损失和预计恢复时间 |
| 春运返程、节假日返程、赛事散场等短时高峰 | 条件纳入 | 若其造成超常态疏运压力，可作为可预见压力情景；需与常态大客流区分 |
| 火灾、警情、管制等公共安全事件 | 条件纳入 | 不研究现场救援和安全处置本身，只研究安全边界明确后的客流疏散和方式协同 |
| 公共卫生事件、恐怖袭击、重大伤亡事故的救援处置 | 原则上不作为主对象 | 只在其导致枢纽客流或运力状态变化时，记录交通后果；不评价医疗、防恐或救援流程 |
| 纯粹行政响应、舆情处置或灾后恢复 | 不纳入核心模型 | 可作为背景和约束，不作为情景库主轴 |

判断一个事件是否进入情景库，至少应回答四个问题：是否改变待疏运人数，是否改变可用服务能力，是否改变可准备时间，是否需要两个及以上主体或交通方式协同。如果四个问题均为否，该事件不宜作为本课题的核心情景。

## 三 不采用单纯事件类型分级

本课题不把“火灾是几级、暴雨是几级、设备故障是几级”作为主线，原因有三点。

第一，事件类型具有开放性和长尾性。真实枢纽运行中可能出现平台故障、道路临时管制、单一通道封闭、天气叠加晚点、信息发布滞后等复合事件，无法预先穷尽所有类型。

第二，同一类型事件的交通后果差异很大。小范围火警可能只造成局部绕行，换乘大厅封闭则可能影响多方式集散；同样是暴雨，若道路通行正常且预警充足，调度压力可能低于道路积水、出租供给下降且夜间集中到达的情形。

第三，交通调度需要的是可执行状态，而不是灾害名称。事件名称能够解释冲击来源，但不能直接给出新增公交、地铁延时、出租引导或接驳组织的数量和时点。调度动作需要依赖受影响人数、服务能力、到位时间、空间范围和不确定性等指标。

因此，本课题采用“事件识别辅助、运行状态分级为主”的口径：

```text
事件输入
  -> 事件类型和位置识别
  -> 运行状态指标抽取
  -> 枢纽调度状态判断
  -> 多方式协同响应建议
```

事件类型回答“发生了什么”，运行状态指标回答“枢纽进入了什么调度状态”，协同响应回答“需要哪些主体和方式准备或行动”。

## 四 事件到运行状态的转译指标

进入情景库的事件，应优先转译为以下指标和约束。这些指标与情景库主轴保持一致，可为后续建模提供输入。

| 指标 | 含义 | 典型来源 | 调度意义 |
|---|---|---|---|
| 信息提前量 P1 | 首次获得可行动信息到预计冲击开始之间的时间 | 气象预警、列车晚点通知、运营调度信息、现场报告 | 判断能否提前备车、延时运营或预置人员 |
| 到达不确定性 U | 对受影响客流到达时刻、规模和恢复时间的未知程度 | 晚点分布、航班恢复预测、道路恢复信息、现场反馈 | 判断采用固定安排还是弹性待命和滚动更新 |
| 冲击持续时长 D | 受影响客流输入或能力损失持续的时间 | 中断时长、晚点持续时间、管制持续时间、天气影响窗口 | 判断一次性疏散还是持续保障 |
| 受影响疏运需求 Q_aff | 在固定时间和空间边界内需要继续疏运的旅客 | 到达记录、滞留记录、客流监测、去向调查 | 判断需要的服务规模 |
| 方式与空间影响 R | 哪些方式、场站、通道、方向受影响及能力损失 | 运营状态、道路状态、场站通行状态、封闭区域 | 判断是否需要跨方式联动和替代路径 |
| 安全与权限约束 S | 是否存在禁止通行、隔离、救援优先或权限限制 | 现场指令、预案要求、公安消防或运营单位决定 | 判断哪些调度动作可做、不能做或需上级确认 |

其中，P1、U、D、Q_aff、R是情景库的核心分析变量；S是不可忽略的约束。若安全约束与运营疏运目标冲突，优先遵循安全和预案要求，再讨论运力协同。

## 五 事件类型作为辅助标签

事件类型仍需记录，但它只是检索和解释标签，不直接决定调度等级。建议采用开放标签，而不是封闭枚举：

| 标签 | 可能事件 | 主要关注的转译项 |
|---|---|---|
| 天气类 | 暴雨、台风、暴雪、高温、大雾 | P1、U、D、道路和车辆能力、航班列车延误 |
| 设施设备类 | 信号故障、电力故障、通道封闭、安检设备异常 | R、C_loss、恢复时间、替代通道 |
| 运输组织类 | 列车晚点、航班延误、末班后集中到达、计划调整 | Q_aff、D、U、夜间可用运力 |
| 公共安全类 | 火情、警情、临时管制、人员聚集 | S、R、疏散方向、禁行区域 |
| 外部交通类 | 道路拥堵、出租蓄车不足、网约车供给异常、公交线路受阻 | 可用能力、到位时间、目的地覆盖 |
| 复合类 | 天气叠加晚点、道路管制叠加夜间到达、设备故障叠加大客流 | 多指标联合变化，需滚动更新 |

若出现未见过的新事件，应先加临时标签，再填写运行状态指标。只要能说明它如何改变需求、能力、时间或安全约束，就可以纳入情景库；不要求事先拥有完整的事件类型库。

## 六 与现行预案和情景库的关系

现行预案负责组织响应、权限、信息报送和现场处置。本课题的情景库负责把事件后果整理为可比较的运营状态，辅助后续分析不同方式何时准备、提供多少能力、服务哪些方向以及如何处理不确定性。二者关系如下：

| 层次 | 主要问题 | 本课题处理方式 |
|---|---|---|
| 事件响应 | 是否启动预案、由谁指挥、谁审批、谁执行 | 引用适用预案，不自行替代 |
| 运行状态 | 需求增加多少、能力损失多少、持续多久、影响哪些方式 | 情景库重点记录和比较 |
| 调度策略 | 地铁、公交、出租、网约车及管理部门如何协同 | 在建模和协同调度模块中分析 |
| 实验评价 | 某种协同策略是否改善清空时间、等待时间或资源使用 | 在实验验证模块中检验 |

因此，情景库不回答“这个事件在行政上属于几级”，而回答“在当前信息和约束下，枢纽进入了哪一种可调度状态”。如果研究材料不足以支撑绝对分级，应先提交指标表、边界条件和数据缺口，不强行给出等级。

## 七 可直接用于说明书的表述

本课题不采用单纯事件类型识别作为情景库构建依据。交通运输系统中的突发事件具有开放性和长尾性，事件类型难以穷尽；同时，同一类型事件在不同客流规模、设施状态、影响范围和持续时间下，对枢纽调度的影响显著不同。因此，本课题将事件类型作为辅助标签，将客流冲击量、影响持续时间、影响范围、服务能力损失、预警提前量和不确定性作为核心分级依据。情景库的目标不是回答“发生了哪一种灾害”，而是回答“枢纽系统进入了哪一种可调度状态”。
