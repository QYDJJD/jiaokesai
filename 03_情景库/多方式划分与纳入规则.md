# 多方式划分与纳入规则

梅玉坤负责部分：T-B3 多方式划分。修订日期：2026年10月10日。用途：明确本课题中哪些交通方式纳入研究，以及它们以什么身份进入情景库、建模和协同调度。

本文件只界定交通方式的研究身份，不等同于现行管理部门的权责划分，也不表示课题可以直接调度所有方式。正式调度权限、运营安排和市场引导措施仍需按适用预案、运营单位规定和平台规则确认。

## 一 定义

本课题所称多方式，并非简单罗列铁路、航空、轨道交通、公交、出租和网约车等交通工具，而是指在超大型综合交通枢纽中共同承担旅客到达、换乘、疏散和离场功能，且在突发事件下具有不同可控性、响应时滞、服务能力和权限边界的交通方式集合。

因此，本课题按“应急调度属性”划分多方式，而不是按传统交通工具名称划分。核心问题是：某一方式在突发事件下是产生客流冲击、可由其运营主体承诺并组织、需要跨主体协调确认、可通过平台或市场机制动员，还是构成能力约束。

## 二 纳入范围

| 类别 | 纳入对象 | 调度属性 | 在本课题中的身份 |
|---|---|---|---|
| 冲击源方式 | 高铁、航班 | 产生集中到达、晚点、滞留和离场需求；本课题不直接调整列车和航班运行计划 | 客流输入、事件来源、到达曲线来源 |
| 运营组织型方式 | 地铁、常规公交、应急接驳公交 | 经有权限的运营主体或主管部门确认后，可承诺延时、加开、短线、接驳等运营行动 | 主要可调度资源、决策变量候选；是否可执行须记录权限主体 |
| 协调型资源 | 储备公交、应急车辆、保障人员、场站组织力量 | 需要跨主体协调、授权和确认，能力相对可承诺，但存在到位时滞 | 提前准备资源、协同资源、能力补充 |
| 企业调度/市场动员型方式 | 出租车、网约车、共享单车、社会车辆、亲友接送 | 政府可协调，企业调度中心或平台可派单、组织蓄车和激励供给，但不能把全部个体车辆视为无条件可承诺运力 | 企业可承诺运力 + 供给响应函数 + 乘客选择 |
| 约束型设施/通道 | 道路、上客点、出入口、换乘通道、安检、蓄车场、停车区 | 不是运输方式本身，但限制各方式有效能力和旅客流动 | 容量约束、瓶颈条件、安全边界 |

上述对象并非全部在每个情景中都启用。某一情景中是否纳入某种方式，取决于它是否改变待疏运人数、可用服务能力、准备时间或协同需求。

## 三 不纳入或只作边界处理的对象

- 高铁和航班的运行图调整、停运恢复、航司或铁路内部调度，不作为本课题直接决策变量。
- 公安、消防、医疗救援等现场安全处置力量，不作为运输方式；其指令作为安全约束和通行边界。
- 私家车和亲友接送若缺少可观测数据，只作为自组织离场或背景流出处理，不作为可承诺运力。
- 共享单车、步行等低容量方式可在局部场景中作为补充选择，但不作为主疏运能力。

## 四 与模型接口的对应

| 类别 | 进入模型的方式 | 典型变量或参数 |
|---|---|---|
| 冲击源方式 | 到达过程和客流需求 | 到达曲线、受影响人数、到达不确定性、晚点持续时间 |
| 运营组织型方式 | 经确认的可调度供给和运营动作 | 加开班次、延时运营、接驳车辆数、服务开始时间、授权与响应时滞 |
| 协调型资源 | 需提前确认的可用能力 | 储备车辆数、人员到位时间、授权时间、资源确认概率 |
| 企业调度/市场动员型方式 | 可承诺供给、弹性响应和乘客选择 | 企业调度量、引导强度、补贴水平、蓄车量、派单响应、选择比例 |
| 约束型设施/通道 | 容量和安全约束 | 通道能力、上客点能力、道路通行状态、封闭区域、队列上限 |

该划分能够直接服务后续建模：冲击源决定需求，运营组织型和协调型资源决定经确认的可承诺供给，企业调度/市场动员型方式决定企业承诺量、弹性供给与乘客选择，约束型设施决定各方式的有效能力上限。

## 五 本课题推荐方案

对虹桥枢纽，本课题建议采用以下默认划分：

| 方式或资源 | 默认类别 | 说明 |
|---|---|---|
| 高铁、航班 | 冲击源方式 | 主要造成到达冲击和滞留，不直接调度其运行计划 |
| 地铁 | 运营组织型方式 | 可研究延时、加开、限流、换乘组织等动作，但必须核实决策主体、授权和响应时滞 |
| 常规公交、夜宵线、应急接驳公交 | 运营组织型方式或协调型资源 | 常规线路和临时接驳经运营主体确认后可形成承诺供给；储备车辆需提前协调 |
| 出租车 | 企业调度/市场动员型方式 | 企业调度中心可直接组织所属车辆，政府可协调蓄车与候客区；其余社会运力按响应函数处理 |
| 网约车 | 企业调度/市场动员型方式 | 平台可派单、激励和组织供给，但可兑现数量仍需按平台响应和道路条件折算 |
| 道路、上客点、出租蓄车场、换乘通道 | 约束型设施/通道 | 限制有效运力和旅客流动，是协同调度必须显式记录的约束 |
| 步行、亲友接送、私家车 | 自组织边界流出 | 可在数据允许时估计流出，不作为主调度对象 |

## 六 可直接用于说明书的表述

本课题不按交通工具名称简单罗列多方式，而是按应急调度属性将其划分为冲击源方式、运营组织型方式、协调型资源、企业调度/市场动员型方式和约束型设施/通道。高铁和航班主要作为客流冲击源，地铁和公交作为经权限确认的可承诺供给，储备车辆和保障力量作为需提前协调的资源，出租车和网约车拆分为企业可调度量与市场弹性响应，道路、上客点和换乘通道作为共同能力约束。

## 七 官方实践校核

- 2025年清明虹桥保障中，地铁延时和加开、公交夜宵线加密、出租与网约车供给组织并行实施，且有交通、公安和执法协同，证明这些方式确实存在联动接口。[上海市政府](https://www.shanghai.gov.cn/nw18454/20250410/78fec666ed1d4c0c8260a6912d85c052.html)
- 2024年铁路突发事件综合应急演练中，铁路启动Ⅱ级响应并与属地单位联动，说明动作须绑定响应主体与权限，不能笼统写成“课题直接下令”。[上海市交通委员会](https://jtw.sh.gov.cn/xydt/20240129/1191c8f1497c4facac19c12339187e76.html)
- 2023年出租汽车保障中，行业主管部门提出保障要求，出租企业调度中心直接调派本企业车辆。由此，出租车既不是完全不可控，也不能把全市场运力视为指令型资源。[上海市交通委员会](https://jtw.sh.gov.cn/xydt/20230220/41fbc0c0d7ac4edeb335ebd48b80340b.html)
