# 情景库与事件评估平台使用说明

平台版本：PLATFORM-02。模型：NETWORK-MILP-02。

**课堂展示入口：**首页现为[单页思路Demo](../../07_成果输出/情景库思路演示.html)，围绕时段、人数和进入节奏展示参数组合及评估差异。直接双击该文件即可离线演示；本机服务的 `/`、`/demo` 与 `/demo.html` 也打开它。下文完整研究流程位于 `http://127.0.0.1:8765/research`，不必在首次汇报逐项展示。

平台现在使用可配置的多方式运输网络。方式、线路、节点和旅客去向由输入卡决定；虹桥是一个示例，其他事件可以使用同一套程序计算。

**研究顺序：组织情景参数 → 评估事件影响 → 匹配既有规则与方法 → 核验应用结果。** 情景库和事件评估为主要研究内容，后续处理采用已有预案或论文方法作为参照，自行实现的网络程序用于验证情景输入及具体约束。

## 先评估事件条件

第一步只需主要需求、初始候客、进入持续时间、信息提前量、进入过程范围、控制目标及基准有效服务。输出各过程的候客峰值、占所设人数上限的比例、预计全部离开时间、完成时限余量、截止剩余及控制条件是否满足。上限为0时按人数检查，不输出无穷大比例。未知与明确为0分开。

当前不会以自拟“现有／加强／联合”三档给事件定级。旧三档输入及结果保留供历史回归，进入当前页面时保存在旧试验字段中，重新按基准有效服务评估。调度程序不以旧标签限制资源。

“既有规则或方法参照”提供铁路晚点路地联动机制、站内突发大客流研究、多方式车辆调度研究三个出处；[来源登记](reference_rules.json)逐项说明对象、查阅范围及迁移限制。可以先不选择参照，只计算指标。当前已取得的资料不足以执行完整、适用于虹桥城市接续的正式等级映射，结果明确标记未自动映射；不从演练中的二级响应、论文摘要或其他车站阈值推造规则。

快速工具仍采用[已有连续队列计算器](../../06_实验验证/分级方法验证/grading_engine.py)，假定这一组人可以接受所填服务、有效能力已处理方向及共用限制。多去向不能相互替代或共享瓶颈未明确时，应拆分或进入网络核验。三种假设进入过程为均匀、80%在前或后四分之一时段进入，没有赋发生概率。默认人数、服务与目标为研究假设，不是虹桥实测标准。

单群体可将主要参数带入细化，更新需求、进入曲线、提前量、控制上限及离开起点截止。目的节点截止保留原输入已有的时间余量；网络、日历、资源和预算仍须核对。多群体自行拆分总量，避免重复填入每个群体。第一步完成仅指离开当前队列，详细模型另查目的节点到达和网络瓶颈。

[专项检查](../../06_实验验证/多方式网络验证/参数预判检查.json)分别统计12项历史兼容性与8项当前事件评估检查；当前12组基准过程另与独立累计实现核对。记录可单独下载，也随完整输入及结果保存；运行时重新计算，避免把手改标签当作结果。固定底板和时段模板尚未独立引用，当前完整情景卡仍逐次保存。

## 一 打开与第一次体验

双击仓库根目录的[启动研究平台](../../启动研究平台.cmd)，打开演示首页。完整工作台地址为 `http://127.0.0.1:8765/research`，也可从演示页底部进入；关闭网页不会自动停止后台计算。

先在第一步评估事件条件，按对象选择既有参照，再进入“事件与目标”选择多方式网络示例，在第五步细化核验。这个例子同时包含地铁、步行换乘、接驳巴士与网约车；轨道既定班次按日历使用，新增运力受到资源和预算约束。

另外三个入口分别是12人手算校验、道路中断后的渡轮接续，以及虹桥真实背景。只有虹桥具有对应的真实业务背景，数值仍为声明假设；其他均为合成示例。

## 二 完整流程

| 步骤 | 填写内容 | 主要核对 |
|---|---|---|
| 事件评估 | 五维相关参数、初始候客、控制目标和基准有效服务 | 输出指标与条件差距，注明既有参照及未映射原因 |
| 事件与目标 | 开始时间、信息提前量、进入时段、两个完成截止、预算、候客与站立要求、来源 | 离开起点与到达目的节点的含义分别明确 |
| 网络与需求 | 候客区、换乘站和目的节点；各群体起终点、可接受方式、初始候客、各过程分时进入 | 每个过程可有不同总人数和去向；新增与初始不重复 |
| 参考资源与方法 | 任意方式、既定能力、资源池、运输与换乘线路、运行时长、日历和共用设施 | 给定服务和可协调增援分开，资源及容量不重复计算 |
| 细化核验 | 检查引用、时序与数量，选择优化或手工核对 | 输入通过、方案可行和独立复核分别判断 |
| 结果与导出 | 网络、方式使用、旅客完成、候客、预约及逐节点人数表 | 方式人次可能重复，不能相加当作已完成旅客人数 |

所有容量均以“每时间步”填写。节点接收按对应到达边界核对；其他服务日历按登乘开始段填写。修改时间步后，原数值不自动变成新的实测能力，须重新检查日历与曲线。

## 三 怎样增加一种方式

1. 在第四步添加方式，填写名称，选择“仅使用已知班次／剩余能力”或“允许协调增加运力”。名称不决定公式。
2. 选择舒适测度。已测度方式填写座位、站立密度及持续时间要求；未测度不代表已经舒适。
3. 为该方式添加线路，指定起终点、登乘与运行时长。需要中间换乘时，增加换乘节点及步行或其他衔接线路。
4. 在既定服务日历中填写各段可用容量；停运段填0。座位与有效站立面积分别填写，有效座位不会超过可用服务能力。
5. 如果确实可以协调增援，再建立资源池，填写每单位容量、可用单位数、全程次数、准备、结束、返回与费用，并在相应线路选择它。
6. 在第三步为相关旅客群体勾选该方式，再校验运行。未接受某种方式的群体不会被强行分配过去。

例如使用已确定地铁班次，应录入轨道站、步行换乘线路、发车时间段和可供本任务使用的剩余能力。报道中的运送人次不能直接作为可用容量。没有录入可用服务数据的方式不会凭名称自动产生运力。

## 四 两种资源池是什么意思

- **周转单位池**：可返回基地重复执行任务的同质车、船等。占用包括登乘、去程、回程及周转准备；去程和回程可不同。不同基地分别建池。
- **分时名额池**：已确认的服务包，按每步最多几包、全程几包、每包几人和单价预约。适用于确认的出租、网约或其他运输服务，不据此推算逐辆车周转。

既定服务不必创建资源池。多个方式和线路可以共用已声明的资源、通道和节点，模型按合计能力核算。登乘位的“可用余量”应扣除既定服务已占用的部分。

## 五 手工验证安排

第四步选择“核对手工运力安排”，按线路填写登乘开始分钟、单位数及可选的周转单位编号。编号留空时按声明的同质资源池自动分配；填写后检查同一编号是否冲突。空预约表表示只使用既定服务。

手工执行器只观察当前进入的旅客，在已知服务日历上寻找最早可到达路径。它不会读取未来需求，也不为手工资源另行求最优客流分配。资源合法但未满足候客或截止时，结果明确显示未通过；计算限时未取得方案与已证明无解分开记录。

可以把优化结果复制成手工安排，再修改、核对。原输入和结果保留在历史记录中。

## 六 输出与手算

完整验证包包含八个文件：输入情景卡、完整计算结果、可打印报告、运力预约表、方式与线路使用表、过程指标对照、逐节点核算表和复现说明。报告可用浏览器打印或另存PDF。

手工核对顺序：

1. 各群体初始候客加逐段新增，得到本过程旅客总人数。
2. 对每个节点核对：上次剩余等待＋新增及换乘到达－本次开始登乘＝本次剩余待登乘。仍在登乘的人数另计入候客空间。
3. 核对各线路登乘、运行、到下一节点和返回时间；旅客不能尚未到站就开始换乘。
4. 核对资源池、节点、共用通道、登乘位及舒适限制。
5. 核对新增预约费用和两个完成时刻，检查截止剩余人数。

**累计与平均不同。**默认目标在各过程取最坏累计全程人分钟：每位旅客从进入到目的节点的分钟数相加。平均全程时间、个人等待和最后完成另报；未完成过程的完整平均时间留空。

**人数与人次不同。**一位旅客步行后乘地铁，会在两个方式中各计一次。真正完成的旅客人数按到达其目的节点独立统计。

## 七 旧卡与虹桥示例

原公交与出租原型的输入、历史结果及报告仍保留。新平台可打开旧记录的原报告；导入旧输入时转换为网络表达，并保留原离开起点截止、另设目的节点到达截止，须重新计算。

虹桥新示例保留23:00开始、05:30离开枢纽的研究目标，并另外要求06:20前到达所设接续节点。6000人和全部运力参数仍为研究假设；没有给缺失的地铁剩余能力赋值。希望比较加入地铁的效果，应另建一份参数来源明确的条件输入。

旧版等待优先与新版全程时间优先，以及两个完成口径的数值，不能直接混作同一实验的改善率。

## 八 范围、保存与技术入口

第一版支持12节点、36线路、12方式、16资源池、8旅客群体、8条进入过程及96个时段。各过程总量与去向可不同。时间步可选5、10、15、20或30分钟；登乘与运行按时间步向上取整。

模型适用于已声明网络的接续运力与路径研究，未自动模拟道路拥堵反馈、轨道闭塞、驾驶员排班、旅客拒乘和现场指挥权限。[数学说明及文献依据](../多方式网络优化/README.md)明确了选择与边界。

用户输入与运行结果保存在 `06_实验验证/平台运行记录/`，已排除Git同步；服务日志位于 `.qa/platform_service/`。数据在本机，主动导出后再分享。需要结束服务时，使用页面“使用说明”中的按钮。

同一求解器的[多事件记录](../../06_实验验证/多方式网络验证/多事件演示结果.json)、[通用性与约束检查](../../06_实验验证/多方式网络验证/通用性与约束检查.json)及[验证说明](../../06_实验验证/多方式网络验证/README.md)单独保存。旧版14项平台检查作为兼容性回归保留，不增加真实事件实证数量。

本工作区已配置运行环境。其他电脑需Python 3.12和[原型依赖](../接续运输优化原型/requirements.txt)中的NumPy、SciPy；网页无外部脚本、字体和图表依赖。
