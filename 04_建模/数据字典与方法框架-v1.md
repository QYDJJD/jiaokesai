## 一 统一统计边界

字典面向突发事件影响下虹桥枢纽的多方式协同疏运，不限定白天或夜间。每个情景独立指定受影响人群、场站、出口、上客区域和统计入口，再确定进入待疏运系统的时点。E01/E02为铁路晚点，E03另分取消未到场、已到场需退改/离场、实际到达待接续人群；E04另分备降和转场。各群体入口和目标分别核，不混入铁路人数。内部步行或换候车队列不重复计入新增旅客。继续出行案例的完成口径建议为“已登乘匹配其方向且具备可行接续的离站服务，或以其他方式实际离开该研究边界”；须由团队确认具体计数点。这一口径表示离开待疏运系统，不等于到达最终目的地。

转入安置、主动取消行程和离开观察范围分别记录。安置不自动计为继续疏运完成；无法判明去向时登记未明转出，不把人数消失当作服务成功。跨案例比较前必须统一人群、窗口、入口和完成定义，当前公开案例尚不满足数值比较条件。

## 二 字段字典

| 字段 | 定义／单位 | 取值依据 | 当前处理 |
|---|---|---|---|
| event_id／scenario_id | 事件与情景身份；字符串 | 来源去重，卡片版本 | 同事件多报道只计一个事件；假设另编号 |
| boundary／cohort／window | 空间、人群、观测起止与时区 | 同口径记录 | 完整起止未取得则标明报道窗口局限；时间用北京时间和完整跨日日期 |
| network_version／service_calendar | 设施版本、事件日、方向运营窗口及临时调整 | 当年设施与当日记录 | 不把2024年底机场联络线回填早期案例；指南不是实际剩余能力 |
| traveller_state／planned_actual_location／onward_goal | 到达、取消、退改、转场等状态，计划/实际地点及目标 | 同一群体或轨迹记录 | 取消未到场不计现场需求；跨机场登机与城市离场分开 |
| U_road／resource_pool／regular_service_cost | 道路运行不确定性、共享资源及常态服务影响 | 区间或误差、车辆人员分配与原服务记录 | 与到达U分开，不重复承诺车辆，不虚构分布和代价 |
| prescribed_limit／measured_time | 规定时限与实测时间分别记录 | 适用预案条款／动作日志 | 首辆到位要求不等于实测τ或服务生效 |
| period_context | 白天/夜间、当时各方式运营时段及服务状态 | 时刻、运营安排及实际状态 | 时段是情景条件；不能仅凭“夜间”断言地铁停运或能力不足 |
| impact_channel／service_restriction_window | 已核的需求、方式、道路、场站或安全影响及服务受限起止 | 事件和运营记录 | 可多项并存；不把服务受限时长替代到达冲击D，纯供给扰动不强行补造到达冲击 |
| t_info／t_target | 首次可行动信息时点／当时预计影响开始时点 | 带发布时间的预测快照 | 缺任一项不由报道下令时间推算 |
| P1 | t_target−t_info；分钟或小时 | 以上同一信息版本 | 负值表示迟获；不是事后实际到达与下令时间之差 |
| U | 决策时点对未来到达的不确定性 | 预测区间、分布或有定义的误差资料 | 保留表达形式及预测时距；实际到达的离散程度不能代替 |
| D | 已定义到达冲击从开始至结束的历时 | 分时到达及冲击识别规则 | 不用报道窗口或服务中断时长替代；规则未定或未核则NA，已核无到达冲击则N/A并说明 |
| Q_aff | 同窗口需要继续疏运的本事件旅客；人 | 到达、去向、自组织离开及边界判定 | “受影响人数”另字段保存；仅确认同窗同界且包含该人群时才可作上界 |
| R | 方式×地点×方向的可用性与能力损失 | 运营、道路、上客点状态及适当基准 | 分项描述；“未见停运报道”不赋正常，动作参与不证明全部能力 |
| B0／A_k／O_k | 初始待疏运、时段进入、实际离开；人 | 同入口、同边界计数 | O_k区分运输、自组织离开、安置及未明转出，不能重复计人次 |
| C_base,m,d,k | 常态服务可用于该方向、人群的剩余服务上限；人/时段 | 班次、已占需求、运行及上客条件 | 不是总额定运力；现有报道不能直接赋值 |
| C_add,m,d,k | 同口径新增有效服务上限；人/时段 | 实际可承诺车辆/人员、停靠方向、道路、装载和周转 | 生效前不计；未知资源不填0，也不填满额能力 |
| t_order／t_ack／t_confirm／t_effective | 同一动作的下令、接令、资源确认、服务生效时间 | 带动作ID的日志 | 现场到车与旅客可实际使用服务需区分 |
| τ_a,m | 同动作同方式t_effective−t_order；分钟 | 可对应的一组时间记录 | 等待时间不代替；提前预置资源单列，不能配上后来的指令造负滞后 |
| constraints | 安全、道路、场站、方向、资源、无障碍、授权及更新时效 | 预案、现场及资源确认 | 未确认只支持核查需求；不能转为执行许可 |
| B_max／T_clear | 峰值待疏运人数／固定群体完成继续疏运历时 | 完整同口径序列与完成定义 | 真实卡当前不可算；合成卡可在明示假设下计算，不回填历史事件 |

## 三 证据与缺失的表示

每个字段同时记录`value、unit、time_basis、boundary、source_id、source_location、evidence_type、missing_reason`。证据属性采用“报道事实、预测、计划、推算、假设、缺失”；“报道事实”表示原文如此报告，不代表取得原始测量。法律标准是否现行、机构是否有权限另记核查状态，不能由来源等级自动认定。

未知值用NA（机器记录可用null），缺失原因至少区分“未公开、未取得、定义未定、口径不可比”。不适用用N/A并说明理由；真实0必须有证据。不得将缺失编码成正常、低风险或零能力。任何推算列出公式、输入与假设；假设值仅进入明确的假设卡，不回填历史事实。

## 四 可用的解析关系与条件

在固定统计系统内，待疏运人数满足：

\[
B_{k+1}=B_k+A_k-O^{transport}_k-O^{self}_k-O^{shelter}_k-O^{other}_k.
\]

这是一项核算恒等关系。运输完成、自组织离开、安置和其他转出互斥登记；若有未明转出或重新进入，另记平衡项或入口记录，不能强行把残差算为运量。即使待疏运B降为0，仍可能有人在安置场所，故不能据此判定原群体继续疏运全部完成。人数守恒核查需要实际流量，容量不能代替O。

针对运输服务，分方向检查实际运输人数不超过同口径可用服务上限；资源、道路、上客点、停靠和权限条件共同限制该上限。不同模式服务同一旅客的连续接驳只在实际离开研究边界时计一次。仅在服务范围可替代且没有共享资源或瓶颈重复时，才允许聚合能力。

未来如建立简化队列递推，须明确时段内到达/离开顺序、时间步长、方向及旅客行为，并检验窗口截尾和残差。写出恒等式不代表已建立预测模型。B_max方向性只在其他条件固定、各时段输入逐点增加或可用服务逐点减少且使用相同队列规则时检查；总需求增加不能单独保证峰值上升。

T_clear须追踪固定群体并给统一起点；观察窗结束仍有人未完成时记“未清空/右截尾”，不能取窗口长度为完成时间。更早可用的资源须允许保留原可行服务安排，不能因强制提前发车而制造“响应更快却效果更差”的模型结论。

## 五 本阶段输入输出与升级条件

当前核心为分级可行性。假设检验已采用本字典的输入/积压区分和逐资源生效口径；参考包版本、K/H来源、各层通过/失败原因及内部标签另行保存。假设可算不代表真实缺失已补齐。

目前输出字段口径、缺失原因、可讨论约束、需要确认的资源和候选评价指标。动作接口见[协同动作接口](../05_协同调度/情景到协同动作接口-v1.md)。

升级为定量研究前，取得同窗口的人群到达/离开、方向、剩余及新增服务、动作时间与安全权限条件，并明确设计、校准、检验事件分组。按数据决定模型和算法；不因章节、库名或公式已经齐备就启动绝对分级。
