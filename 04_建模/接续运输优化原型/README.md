# 接续运输优化原型

版本：OPT-MILP-01。实现日期：2026年10月19日。

这是可以运行的混合整数线性规划原型，承接[模型研究方案](../情景库驱动的接续运输优化模型研究方案-v1.md)。它读取[完整情景输入卡](../../03_情景库/模型输入卡-虹桥降雪背景.json)，搜索公交发车任务及分时出租服务预约，再按允许的旅客进入过程分配服务。计算结果见[实验结果](../../06_实验验证/优化模型验证/优化实验结果.json)和[策略输出](../../05_协同调度/优化模型输出/README.md)。

## 一 已实现范围

- 三个明确标注的合成方向，基础地面服务、可调备用公交、已确认出租服务名额。
- 公交候选任务、班次上限、准备时间、站位占用、运行与返回、备用车队及实际车辆编号。
- 出租每时段及累计预约上限；费用按已预约名额计，未使用名额也计费。
- 分方向人数守恒、进入前不能服务、候客上限、完成截止、共享上客及下游接续容量。
- 核定车辆容量、站立密度和累计站立人分钟限制；等待、候客密度和乘车耗时分别报告。
- 所有允许过程共用同一资源计划；相同观测历史下的旅客分配相同。
- 等待优化、费用择优、固定资源后的等待及站立负担整理；预算和舒适要求变化实验。
- 独立事件/FIFO复算、可穷举小例、无解及错误输入检查、集合外压力过程。

当前以备用公交为车源，没有调出常态公交，因此没有用缺失的原线路客流计算常态服务损失。出租上限是有效服务名额，不是逐辆出租周转模型。地铁事实保留在案例背景，不把273运送人次解释为剩余能力。没有温度、振动或主观满意度标定，没有全市道路拥堵反馈及自动驾驶训练。

基础接续及增援出租在本例中按有座服务假设，站立人数只计算备用公交。结果中的“公交全员有座”指将公交站立上限设为0，并不代表已经调查过各实际方式的座位情况。

## 二 参数与决策

输入的五维分别转换为准备可用时刻、允许的进入过程、进入窗口、固定任务人数，以及方式／设施状态。模型还需要初始候客、方向、车辆与站位、服务日历、容量、费用、舒适目标和截止等必填细节。只给五维标签或已有保障等级，程序不会据此推造数据。

| 决策或状态 | 数学含义 | 代码 |
|---|---|---|
| 选择公交任务 | 方向、登乘起点与离站时刻已定义的任务是否启用 | bus，二元变量 |
| 出租服务预约 | 每方向每时段预约多少个服务包；示范每包10个服务名额 | taxi，整数变量 |
| 分方式服务人数 | 给定进入过程下，本时段实际完成多少人 | serve，非负连续变量 |
| 期末候客人数 | 本时段服务后的剩余人数 | q，非负连续变量 |
| 站立人数辅助量 | 每班服务人数超过座位数的正部的上界 | standing，非负连续变量 |
| 最坏等待 | 允许过程内最大的累计等待人分钟 | worst_wait，非负连续变量 |

人数采用连续人流近似，因此可能出现小数；公交任务与出租预约服务包保持整数。三个方向不是实测虹桥分担率。所有模型数值的事实／假设属性写在输入卡中，10008名受影响旅客未被当作6000名接续任务的估计依据。

## 三 数学关系

令进入过程为 s，方向为 d，时段为 t，公交候选任务为 j，时间步长为 Δ。以下符号只用于技术表达，输出表使用中文。

### 目标与求解顺序

第一阶段最小化最坏累计等待：

\[
\min Z,\qquad Z\geq\Delta N+\Delta\sum_{d,t}Q_{sdt}\quad(\forall s).
\]

其中 N 包含新增旅客和初始候客。该式对应段初进入、段末完成服务的离散模型：每个任务旅客至少在一个时段内等候；它不等于连续进入条件下的精确等待。不同进入过程没有赋予概率。

第二阶段保持取得的等待上界，减少预约费用。随后固定整数资源安排，用线性求解减少各过程累计候客，再在同一等待水平下减少站立人分钟，避免非最坏过程出现无必要的滞留。整理阶段的求和仅用于平局处理，不解释为各过程的发生概率。

每一阶段记录求解状态、用时、可行目标、求解界限和相对差距。状态为限时但已有可行解时，保留经核对的排班，不写为已经证明全局最优；只有状态为不可行时，才报告当前候选集合内无解。

### 人数、服务与完成

\[
Q_{sdt}=Q_{sd,t-1}+A_{sdt}-\sum_m Y_{sdtm},\qquad Q_{sd,-1}=B_d.
\]

各方式服务量不超过基础可用能力、所选公交有效容量或已预约出租名额；非负候客确保不服务未来旅客。安全上限检查的是服务前人数，即上期候客加本期进入，并同时检查分方向和全体上限；截止边界的期末候客为0。

### 车辆与设施

每时刻仍在登乘、行驶、回程和必要准备中的公交任务数不超过车队规模；处于登乘期的任务数不超过站位数。该原型为同质备用车、相同枢纽起讫的固定返回任务；汇总占用通过后，用区间分配生成逐辆车的任务表，再独立检查车辆编号与时序。当前基准为一处公交站位。

共享上客限额约束实际服务量。各方向各方式的运行时间将实际离站人数移到对应到达时段，再检查下游接续节点的开放窗口和容量；不能把人转运至不可接续节点后算成功。

### 舒适与费用

\[
U_{sdt}\geq Y_{sdt,\text{公交}}-\text{座位数}\sum_{j\in(d,t)}X_j,\quad U_{sdt}\geq0,
\qquad\sum_{d,t}\text{乘车分钟}_d U_{sdt}\leq\text{站立负担上限}.
\]

公交有效载客上限同时受核定容量和“座位数＋可站立面积×允许站立密度”限制。上述物理暴露结构借鉴[舒适度文献比较](../情景库驱动的接续运输优化模型研究方案-v1.md)中的状态及时间表达，没有移植外国铁路感知倍率，也不把站立人分钟当作满意度分数。整理阶段将辅助量降到实际需要的水平；独立程序直接从实际公交载客量重新计算站立负担。

费用为所选备用公交任务费用与出租服务包预约费用之和，不超过预算。基础服务费用为所有方案共同条件，本原型比较增量费用；费用、票价与社会总成本不混用。

### 信息时序

公交任务和出租预约在允许过程间完全相同。旅客分配只能使用已观察的进入历史：若两个过程到当前时段的进入历史一致，其本时段分方式服务量必须相同。有限情景树中，观测后能够区分的分支可以产生不同分配；不能将其解释为对未列未来过程也有保障。

## 四 时间约定与复算范围

基准每10分钟一段，旅客在段初以批量进入，服务在段末完成。这是明确的离散服务模型，服务前候客峰值含正在等待本段完成的人群。登乘窗口用于占用站位，未另外建立逐人装载速率和行人移动模型。

`simulate.py`按事件和一分钟计时累计候客面积，再逐批次按先到先服务核对等待，并重建实际车辆、方式与下游容量；它没有调用优化约束矩阵。分钟核对仍使用同一批量进入／段末完成约定，不是另行获得一分钟真实需求，也不是完成了连续模型的步长收敛证明。

旅客在每个方向内具有相同可接受方式，按先到先服务分配；未实现异质票价接受、拒乘及无障碍人群的内生选择。初始旅客的等待从当前决策时点计，不推造此前已等待时长。真实事件仅辅助核对任务和组织背景；6000人、方向、能力、车辆、成本、舒适与阈值均为研究假设。

## 五 运行与复现

使用Python 3.12、NumPy 2.3.5、SciPy 1.16.3，求解器由SciPy调用HiGHS。接口和状态含义见[SciPy官方说明](https://docs.scipy.org/doc/scipy-1.16.0/reference/generated/scipy.optimize.milp.html)。依赖见[requirements.txt](requirements.txt)。项目本轮运行时将SciPy单独放入被忽略的 `.qa/model_runtime`，程序允许读取该隔离位置，不修改系统Python安装。

标准环境安装依赖后，从仓库根目录运行：

```powershell
python -m pip install -r 04_建模/接续运输优化原型/requirements.txt
python 04_建模/接续运输优化原型/build_input.py
python 06_实验验证/优化模型验证/test_model.py
python 04_建模/接续运输优化原型/run_experiments.py 35
```

最后一个参数是每个优化阶段的秒数上限。生成输入卡命令会重建声明的研究示例；修改卡片后可直接调用求解程序，勿再次重建覆盖自定义参数。批量实验逐项保存检查点；完整结束后输出汇总、具体班次、预约名额、对照和候客图。

本目录固定Python文件使用LF换行，以便不同系统检出后仍能核对存档代码哈希。直接复核现有结果可运行 `python 06_实验验证/优化模型验证/verify_saved.py`，无需重新求解。

## 六 当前结论边界

小例穷举检查代码能否算对；合成过程和预算／舒适实验检查模型机制；真实事件资料辅助说明对象、服务与时段。三类证据分别使用。新模型的通过结果不借用此前分级原型的验证次数；没有把优化模型中的费用下降写成虹桥实际节省。
