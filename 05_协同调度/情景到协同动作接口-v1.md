# 情景到协同动作接口 v1

最新等级按[分方向规则v2](../03_情景库/分方向与共享约束判级规则-v2.md)取已列共同通过方案的最低层。失败不证明同层全部调度策略无效；个人最长等待仅补充，实际执行需相应业务条件。

10月11日补充：用户已选择等级表达“需要哪档运力保障”，以[分级规则](../03_情景库/分级规则与判级依据-v1.md)为准。等级指预设供给曲线的最低通过层，不证明包内所有调度策略无效，不产生执行授权。

日期：2026年10月10日。用途：将描述性情景转为有条件的候选动作与信息核查，支撑后续讨论。当前没有调度求解、资源承诺或已获批的操作规程。历史主体动作见[联动现状](../01_文献资料/多方式联动现状-T-C2.md)，定义见[协同联动方法](../03_情景库/协同联动定义与方法.md)。

## 一 从信息到动作的接口

流程为：更新事件信息 → 核安全及运输可用性 → 核旅客方向与可用服务 → 请求/确认资源 → 提出候选协同安排 → 记录生效与旅客反馈 → 更新或终止。发现安全不明时优先要求核查；未知不直接推断禁用，也不视作可执行许可。

| 动作字段 | 最少记录内容 |
|---|---|
| action_id／scenario_id | 动作与情景版本；一张卡可含多动作 |
| evidence_role | 历史已报道动作、事前计划或研究建议，分别标记 |
| trigger | 条件和原文/假设依据；无阈值不填写某等级自动触发 |
| requester／decision_owner／executor | 请求方、决策/授权主体、执行方；未知分别待核 |
| resource_commitment | 方式、车辆、人员、地点、方向、时段及承诺状态；请求量不等于兑现量 |
| t_order／t_ack／t_confirm／t_effective | 同动作时间链及来源；未取得保留NA |
| service_scope | 停靠、可上客人群、目的地和接续限制；名义运力不能无条件替代 |
| safety_and_authority | 适用预案及版本、禁用/限制条件、资源冲突和权限核查 |
| feedback／stop_condition | 是否生效、服务量、未完成原因、更新和终止依据 |

## 二 条件化候选动作表

下表均为研究建议。相关主体是需要核查的接口对象，不是新指定的指挥关系。

| 情景条件 | 依据 | 候选动作及接口对象 | 执行前必要条件 | 当前输出 |
|---|---|---|---|---|
| 到达安排变化、预计接续可能不足 | SC-E01/E02为铁路晚点，SC-E04为航空转场；来源与人群分列 | 请求受影响到达方式的信息接口更新分时到达；向协调机构及运营单位确认可提供服务 | 预测时点、对象、共享路径、响应职责和更新频率；按铁路、航空等分别核接口 | 信息请求清单；不设启动人数 |
| 候选轨交/公交仍具服务方向条件 | SC-E01有实际延时/加密，RF-P01有方向性计划 | 与运营单位核延时、加开或接驳候选方案 | 运能余量、检修、安全、人员、方向、停靠、正式批准及生效时间 | 可核候选安排；不承诺班次数或最迟下令时点 |
| 出租资源可参与但承诺数量未知 | SC-E02有企业动员线索 | 与企业或适当平台确认动员方式、可承诺车辆和反馈；匹配旅客去向 | 驾驶员响应、到位、上客空间、道路、服务兑现和权限 | 请求/动员/承诺/到位分别记录；不假设统一支配全部车辆 |
| 到达与上客空间可能冲突 | SC-G01有出口分流和上客组织 | 向现场管理及公安等适用接口核动线、临时上客点和引导方案 | 场所容量、安全通道、无障碍、管控授权、车辆周转 | 空间方案核查项；不能由泊位数推服务率 |
| 运输安全或路线可用性未确认 | SC-E03有运行调整/恢复及设施准备；安置启用未知 | 核可用方式；必要时按适用预案转介安置/救援协调接口 | 危害状态、禁用范围、场所容量、启用授权和特殊人群需求 | 安全核查/转介分支；安置不计为继续疏运完成 |
| 航空取消或转场改变旅客状态/地点 | SC-E03、E04 | 核机场与航司信息，分列退改、城市离场、跨机场和留候接口 | 实际地点、后续目标、道路、上客点、下游服务、授权和生效 | 分群体条件；未到场取消旅客不计现场人数 |
| 已确认某区段服务中断，拟以接驳替代 | SC-E03；PL03；RF-P02仅计划参考 | 核可用节点路径和公交/出租等增援 | 下游服务、常态剩余、调出原服务代价、承诺车辆；规定时限与实测分开 | 候选替代接口，不把一方式恢复推成全部完成 |

## 三 如何解释卡片差异

E01、E02均为晚点类，但可用证据不同：E01能描述跨方式保障，E02能补企业内部动员。区别支持不同的信息核查重点，不能据此认定两事件采用不同最优策略。G01帮助区分有准备的高峰；E03增加时变供给及安全分支；E04增加跨机场地点/目标；P01/P02要求方向、时段和下游接续；D01用于流程检查。

若候选主轴相同但安全、权限或服务方向不同，应保留不同约束和动作分支，不能直接合并。反之，字段变化但未产生可解释的动作差异时，暂不宣称发现新的情景类型。

2022总体和轨交保障接口本轮已有原文依据，详见[制度核查](../01_文献资料/虹桥预案与制度接口核查-2026-10-10.md)。按规定职责记录与具体执行确认分开，不能将历史制度或规定首车到达要求作2026自动执行许可或实测时延。

## 四 边界与后续交付

历史报道能说明某年某事件的参与和动作，不证明2026年现行正式授权；HOC/ERC已有联动、预警和电子预案，研究重点是组织本组证据与比较接口，不能宣称创建虹桥此前不存在的协同系统。

本阶段交付上述条件化接口。后续取得资源、权限和时间记录后，才比较可执行策略、算指标及检验效果。正式责任和终止规则由适用预案及实际确认确定。
