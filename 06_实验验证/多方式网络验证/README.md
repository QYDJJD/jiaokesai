# 多方式网络模型验证

对象：NETWORK-MILP-02，不与旧公交及出租原型的测试次数合并。

## 已完成的检查

[24项自动检查](test_network.py)及[结果](通用性与约束检查.json)覆盖：方式名称和编号替换、新增第五种方式、四方式换乘、渡轮网络、停用与取消班次、不同总需求、多起终点、方式接受限制、两个完成截止、既定服务权限范围、换乘节点候客、座位与站立、共享通道、实际单位冲突、登乘位、仍在登乘的人数、信息因果性、未来旅客、零预算、零需求、手工目标失败以及旧卡转换。小例用穷举日历另行核对最优累计全程360人分钟。

## 同一求解器的四个示例

[复现程序](run_examples.py)从[示例输入生成器](../../04_建模/多方式网络优化/network_examples.py)读取四张不同卡，经同一[求解器](../../04_建模/多方式网络优化/network_model.py)与[独立核算器](../../04_建模/多方式网络优化/network_audit.py)计算，保存[多事件结果](多事件演示结果.json)。完整包存入 `.qa/network_reproduction/`，版本化摘要保留源文件和输入哈希。

| 示例 | 本轮结果 | 说明 |
|---|---|---|
| 单车12人 | 费用200元，平均等待20分钟，平均全程30分钟；第60分钟离开起点，第70分钟到目的节点 | 穷举目标与优化一致；两个完成口径不能混用 |
| 四方式120人 | 费用190元，两个进入过程均通过；最坏平均全程约40.33分钟 | 实际使用步行、地铁、接驳巴士与网约车，包含中间换乘 |
| 道路中断与水路接续80人 | 使用步行及渡轮，第60分钟到目的节点；新增预约费0元 | 既定服务为共同条件，0元不是实际运输免费 |
| 虹桥真实背景6000人 | 新增预约费23960元，6个周转单位执行18次，164个10人服务包；四过程通过 | 保留05:30离开起点目标，另设06:20到目的节点截止；本轮最晚06:10到达 |

虹桥首阶段相对求解差距约0.0829%，在所设0.1%差距内；没有称为精确全局最优。其余示例的状态和界限逐项记录，纯线性问题可能不返回整数求解差距字段。

上述比较用途是验证输入结构、模型机制和程序一致性。四张卡不是实际成功率样本；虹桥没有实测分时需求与原排班，不能认定为历史回放或实际节省。旧版等待优先和新版累计全程优先、不同完成口径之间不直接报告改善率。
