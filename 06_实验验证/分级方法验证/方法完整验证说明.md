# 情景库分级方法完整验证

日期：2026-10-11；版本METHOD-VALIDATION-COMPLETE-01。研究范围为已声明的连续队列、预定方案和有限到达过程集合。依据[理论推导](../../03_情景库/分级方法成立条件与理论验证-v1.md)，完成学生方法研究所需的验证，不将真实运营部署列为当前验收条件。

## 独立核算方法

[independent_reference.py](independent_reference.py)不导入原分级引擎、分配检查或搜索代码，以累计进入与累计服务的反射公式计算队列，使用有理数运算。原引擎按进入率与服务率逐段积分，两者实现路径不同。数值输入转为可表示的有理数，转换分母上限10^9；原程序与参考核算的指标误差要求≤1e-6。

“独立”指公式与代码实现的交叉核算，不指另一研究团队或真实现场样本。新增算例在既有程序固定后按随机种子20261012生成，保存全部输入和SHA-256，结果不是人工逐条指定。它们检验原32卡之外的计算一致性，不称为真实事件留出验证。

## 完成结果

| 验证内容 | 规模与判据 | 实际结果 |
|---|---|---|
| 原情景卡交叉核算 | 18张单池、14张方向及边界卡，比对完整等级 | 32张全部一致 |
| 新分时供需过程 | 600组，核峰值、完成时间、截止积压、未完成、已完成与总人数六项指标 | 全部一致；最大绝对误差4.55×10^-13 |
| 新方向情景 | 120组两或三方向、三种联合到达、三层预定方案、共享上客及候客条件 | 全部等级一致；F0/F1/F2/F3分别1/3/6/110 |
| 解析边界 | 108组目标条件，每组服务率取解析门槛的99%、100%、101%，共324次 | 全部符合解析判定，包括B0>K的不可行情形 |
| 目标敏感性 | 72组情景各取K=750/1000/1250与H=0.5/1/2，共648组 | 等级均与独立核算一致；38张有跨级，34张在所选范围内不变 |
| 条件变化关系 | 目标放宽432次比较；新方向情景的需求、目标和不确定性360次比较 | 全部符合理论规定的变化方向 |
| 补充等待指标 | 12个单批旅客、延迟生效服务的最长等待解析例 | 全部一致 |
| 错误规则识别 | 7个具有明确反例的错误简化 | 全部检出 |

七个错误规则分别为：遗漏到达节奏；合并不可互换方向；遗漏共享上客限制；将早期闲置服务留给后来旅客；颠倒同一方案与所有到达过程的量词；将不同时刻的峰值相加；将未知能力当作零能力。结果见[完整JSON](方法完整验证结果.json)。

## 验证所支持的结论

十类检查全部通过。方法在所声明模型和方案域内，能完整判定两个主条件并选出最低通过层；关键字段有解析或对照依据，结果可复算。324与648是不同实验的运行次数，不与情景卡数量混合统计。随机情景的等级分布不代表真实频率，也不证明现实运营效果。

F3的结论范围取决于方案域，这是等级定义的一部分。真实案例承担对象与约束的事实依据，合成与解析实验承担计算验证；两种资料共同服务方法研究。取得现场时序数据属于实际部署条件，不是本研究验证失败。
